# Spring Batch を使うか、素の Spring Boot で済ませるか

## 基本方針

**迷ったら素の Spring Boot で始める。** Spring Batch は、下記「Batch を選ぶ条件」のいずれかに明確に当てはまる場合にのみ導入する。

業務ロジックは application 層・domain 層に置き、Spring Batch や起動方式に依存させない。詳細は [architecture.md](architecture.md)。

## Batch を選ぶ条件（いずれかに該当）

| 条件 | 具体例 |
|---|---|
| 途中からの再実行が必要 | 100 万件中 60 万件目で失敗したとき、最初からやり直すと業務時間内に終わらない |
| 件数が多く、一定件数ごとにコミットしたい | 1 トランザクションに収まらない量を chunk 単位で処理する |
| スキップ・リトライの方針を宣言的に持ちたい | 不正データは N 件までスキップして続行、一時的な DB エラーは 3 回リトライ |
| 実行履歴と二重起動防止を DB で管理したい | 同じ業務日付のジョブが二度走ることを、パラメータ単位でフレームワークに防がせたい |
| 複数ステップを条件分岐でつなぐ | 取込 → 検証 → 失敗時は後始末ステップ、成功時は集計ステップ |
| 並列化・分割処理が必要 | パーティショニングで範囲を分けて並行処理する |

## 素の Spring Boot で済ませてよい条件（すべてに該当）

- 処理量が 1 トランザクション、または単純なループ内の小さなトランザクションで収まる
- 失敗時は最初から再実行してよい（処理が冪等である、または冪等にできる）
- 実行履歴はジョブ管理ツール（スケジューラ）とログで足りる
- ステップ間の複雑な分岐がない

## 素の Spring Boot で作る場合の決まり

- 起動口は `ApplicationRunner` とし、web サーバは起動しない（`spring.main.web-application-type=none`）
- 終了コードを `ExitCodeGenerator` で返し、スケジューラが成否を判定できるようにする
- 処理は冪等に作る（同じ入力で二度実行しても結果が同じ）
- 二重起動の防止が必要なら、スケジューラ側の排他、または DB のロック表で行う（自前で凝った仕組みは作らない）

## エージェントへの指示

新規バッチの作成を頼まれたら、実装に入る前に、上の条件表に照らして「Batch / 素の Boot」のどちらを選んだかと、その根拠を一行で利用者に示すこと。条件が要件から読み取れない場合は、再実行要件と処理件数の2点だけを質問する。
