# 実装計画

設計図をどう実装するかの計画。新規開発でも変更でも、実装に入る前に毎回1つ作り、設計図とともに利用者の承認を得る。

## 置き場所

`docs/batch-specs/plans/<yyyyMMdd>-<ジョブ名>-<要約>.md`（例: `20261019-monthlySalesSummaryJob-skip-limit.md`）

作った後の計画は書き換えない。変更のたびに新しい計画を作る。実施後に追記するのは「結果」の節だけとする。

## 書くこと

```markdown
# <ジョブ名>: <要約>

- 日付:
- 種別: 新規 / 変更
- 対象: docs/batch-specs/<ジョブ名>.md, docs/batch-specs/<ジョブ名>.design.md
- 変更の要約:（変更の場合。仕様書の差分を1〜3行で）

## 手順

| 順 | 作業 | 社内スキル | 引数 |
|---|---|---|---|
| 1 | 集約 MonthlySalesSummary を追加 | add-aggregate | 集約名=MonthlySalesSummary, ... |
| 2 | ... | （なし。本スキルの決まりで作る） | |

## 直す・作るファイル

- （パスと、何をするか）

## 結果

（実施後に追記する。計画どおりに済んだか、計画と違うことをした場合はその内容と理由、ビルドとテストの結果）
```

社内スキルを使わない作業も、手順の表に「（なし）」として書く。
