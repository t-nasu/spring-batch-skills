# 0002 迷ったら素の Spring Boot

## 背景

Spring Batch の機能を必要としないバッチも多い。フレームワークを導入すると、サポート期間が切れたときの版上げなど相応の費用を払い続けることになる。

## 決定

迷ったら素の Spring Boot で始める。Spring Batch は、途中からの再実行、chunk 単位のコミット、宣言的なスキップ・リトライ、DB による実行履歴と二重起動防止、条件分岐のある複数ステップ、並列化のいずれかが必要な場合にのみ使う。

Spring Batch を入れた場合に増える費用: JobRepository のテーブル（`BATCH_*`）の管理、メジャー版での API の破壊的変更への追従、フレームワーク固有の概念の学習。

業務ロジックを application・domain 層に置き、Batch や起動方式に依存させないことで、後から Batch へ移す（またはその逆の）費用を小さく保つ。
