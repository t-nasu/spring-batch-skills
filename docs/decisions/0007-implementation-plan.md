# 0007 実装計画を設計図とは別に残す

## 背景

社内スキルを呼ぶ順や引数を開発者が確認できるようにしたい。ただし設計図は仕様書とともに残り続ける正本であり、社内スキルの引数の定義が変われば古びる手順の話を混ぜたくない。

## 決定

- 設計図には、引数の元になる設計の中身（集約名と新規か既存か、テーブル物理名、ユースケース名、値オブジェクト）だけを書く
- 社内スキルの名前・順・引数は実装計画に書き、設計図とともに承認を得る
- 実装計画は `docs/batch-specs/plans/` に、新規開発や変更のたびに1つずつ残す。作った後は書き換えず、実施後に「結果」だけを追記する。何をどう作ったかの履歴として使う
