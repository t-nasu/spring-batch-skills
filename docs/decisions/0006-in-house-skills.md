# 0006 社内スキルとの関係

## 背景

社内には、ドメイン・ユースケース・リポジトリ・Mapper の追加（`add-*`）や点検（`review-*`）のスキルがすでにある。いずれも、開発者が名を指し、引数を渡して呼ぶ手順書の作りである。社内の資料はこのリポジトリには持ち出せない。

## 決定

- 本スキルは社内スキルのルールをコピーせず、名前で示して従わせる。コピーすると、社内スキルが更新されたときに食い違うため
- 社内スキルと本スキルが食い違うときは社内スキルに従う。ただし次は本スキルを優先する
  - application 層の命名は `UseCase`。社内スキルには「Service に移譲」とあるが、別の社内文書に「application 層は Service ではなく UseCase」という決まりがあり矛盾している。`UseCase` を優先する
  - chunk の Reader の作り方は開発者が選ぶ（[0003](0003-chunk-reader-mapper.md)）
- `add-inbound-batch`（新規バッチ・スケジュールタスクの追加）は当面使わない。Runner による単発とページング逐次の二方式を扱うもので、本スキルとの役割分担は後で決める
- 社内スキルは今後も増減するため、本スキルでは名前を列挙しない。`add-` と `review-` という名前の付け方で社内スキルを見分け、作業ごとに説明文から合うものを選ばせる（2026-10-19 に列挙をやめた）。選んだスキルは実装計画に残るので、開発者が承認のときに確かめられる
- `add-inbound-batch` も名前では示さず、「バッチやスケジュールタスクの入口を追加する社内スキル」として除外する
